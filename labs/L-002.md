# L-002 · Parserkorrekturen im Agent-Loop

**30 Minuten, Zweierteams.** Starten Sie mit dem Draft aus L-001. Ziel ist ein grüner Integrationsstand für das SemVer-Feature. Die Quiet-Änderung und eigene Tests bleiben erhalten.

## 0–7 Min · Befund und Hypothese

Öffnen Sie den roten Check des Drafts und reproduzieren Sie die drei Fehler mit `python -m pytest tests/test_parser.py -q`. Ordnen Sie die Fehler zu. BUG-1 speichert den Scope mit Klammern. BUG-2 erkennt das `!` nicht als Breaking Change. BUG-3 behandelt Großschreibung und Whitespace fehlerhaft. Benennen Sie je Fehler eine erwartete Ausgabe und eine Hypothese.

## 7–21 Min · Folgeauftrag auf demselben PR

1. Übernehmen Sie den nachvollzogenen Scope-Fix aus D-002 in Ihren PR oder geben Sie ihn als ersten abgegrenzten Schritt mit.
2. Geben Sie dem bestehenden Cloud-Lauf PR-Link und Head-Branch. Lassen Sie BUG-2 und BUG-3 getrennt planen und testen, mit je einem erklärbaren Diff. Wechseln Sie nach BUG-2 die Rollen bei der Prüfung. Ein vorhandener Testbefund bleibt erhalten, bis der Code ihn behebt.
3. Vergleichen Sie den Agent-Diff mit Ihren Hypothesen. Prüfen Sie, dass nur der Commit-Typ normalisiert wird und der Betreff seine Schreibweise behält. Führen Sie die vollständige Suite aus. Zehn optionale Skips sind erwartet.

**Prompthilfe.** „Arbeite auf dem Head [Branch] von [PR]. Behebe die anhand der drei Parser-Tests bestätigten Fehler in getrennten Schritten. Erhalte Beschreibung, Quiet-Funktion und bestehende Assertions. Zeige Zieltests und Gesamtsuite. Pushe nur auf den bestehenden Head. Kein neuer PR oder Merge.“

## 21–30 Min · Erneute Prüfung und Übergabe

Ordnen Sie den neuen Actions-Check dem neuen PR-Head zu. Wechseln Sie nach grünem Check von Draft zu Ready und bitten Sie die andere Person bzw. ein anderes Team um unabhängiges Review. Prüfen Sie offene Threads. Der berechtigte Mensch übernimmt den PR im Übungsrepo erst nach Freigabe und erfolgreichen Checks. Halten Sie die Integrations-SHA für L-003 fest.

**Fallback.** Lokale Korrektur auf demselben Head und manueller Push, sofern verfügbar. Bei ausstehender Freigabe oder fehlendem GitHub für L-003 auf die bereitgestellte grüne Referenz `m002` wechseln. Den ursprünglichen PR offen lassen und fehlende Nachweise kennzeichnen.
