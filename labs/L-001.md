# L-001 · Erster Agent-Auftrag mit Cursor

**30 Minuten, Zweierteams.** Eine Person steuert den Lauf, die andere prüft Anforderungen und Nachweise. Ausgangspunkt ist das eigene RelNotes-Kursrepo auf `main`. Ziel ist ein offener Draft-PR für `--quiet`, der in L-002 weitergeht.

## 0–7 Min · Auftrag und Ausgangslage

1. Lesen Sie `AGENTS.md`, `src/relnotes/cli.py` und die vorhandenen CLI-Tests. Verwenden Sie dafür den lokalen Workspace, bei Bedarf den lokalen Cursor Agent zum Lesen und Erklären.
2. Testen Sie mit `python -m pytest -q`. Notieren Sie die drei bekannten Parserfehler und zehn übersprungenen Feature-Tests getrennt vom Auftrag.
3. Schreiben Sie ein GitHub-Issue. Mit `--quiet` oder `-q` entfällt die Statistik auf stderr. Markdown auf stdout bzw. in der Zieldatei und Exit-Code bleiben erhalten. Ohne Option erscheint die Statistik wie bisher. Formulieren Sie einen eigenen Fall, etwa mit Ausgabedatei oder ungültiger Zeile.

## 7–20 Min · Cloud-Lauf

Öffnen Sie Cursor Web, wählen Sie Repo und `main`, fügen Sie den Issue-Link und Ihre Kriterien ein. Prüfen Sie den Plan, lassen Sie auf einem Arbeitsbranch implementieren und einen PR gegen `main` öffnen. Führen Sie parallel die CLI-Gegenprobe lokal aus. Wenn nur der Branch entsteht, öffnen Sie den Draft selbst. Machen Sie einen bereits geöffneten PR bei Bedarf zum Draft.

**Prompthilfe nach dem eigenen Versuch.** „Bearbeite [Issue-URL] für RelNotes auf einem Arbeitsbranch. Nenne zuerst Plan und betroffene Dateien. Ergänze einen Regressionstest für die Ausgabe. Führe den CLI-Zieltest und die Gesamtsuite aus. Belasse die bekannten Parserfehler. Öffne einen PR gegen main und nenne Testbefehle sowie Ergebnisse. Kein Merge, keine Workflow-Änderungen.“

## 20–30 Min · PR prüfen und übergeben

- `python -m pytest tests/test_cli.py -q` sowie CLI-Aufruf mit und ohne `--quiet` prüfen. Falls möglich den PR-Head lokal auschecken.
- Diff, Branch, PR-Basis, Logs des Agenten und den Actions-Check vergleichen. Erklären Sie, welche Fehler schon auf der Basis vorhanden waren.
- Draft offen lassen. Issue, Agent-Lauf, PR, Head-SHA und Entscheidung „zurückstellen wegen bekannter Baseline-Fehler“ im Arbeitsnachweis vermerken.

**Fallback.** Nach fünf Minuten ohne Fortschritt auf demselben Branch lokal mit Cursor oder manuell weiterarbeiten. Der Mensch pusht und öffnet den Draft. Ohne GitHub dokumentieren Sie Branch, Diff und lokale Tests. Der Trainer stellt bei Bedarf `m001` zur Prüfung bereit, inklusive der separaten Demo-Option.
