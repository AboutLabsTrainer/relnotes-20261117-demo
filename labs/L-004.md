# L-004 · CI-Gegenprobe und Merge-Entscheidung

**45 Minuten, Zweierteams.** Verwenden Sie den offenen SemVer-PR aus L-003. Der Trainer hält einen separaten Trainings-PR für die Gegenprobe bereit, falls am Feature-PR noch ein fachlicher Blocker besteht.

## 0–10 Min · Aktuellen Stand und Regeln prüfen

Prüfen Sie Basis, Head-SHA, Diff und den Workflow `.github/workflows/ci.yml`. Der Check `RelNotes tests` installiert das Projekt und führt pytest aus. Ordnen Sie den grünen Lauf dem PR-Stand zu. Ein PR-Lauf kann einen von GitHub erzeugten Test-Merge-Commit verwenden. Prüfen Sie den tatsächlichen Testschritt. Kontrollieren Sie Required Checks, unabhängiges Review und mögliche Bypass-Rechte. Halten Sie den wirksamen Schutz fest.

## 10–30 Min · Grün, Rot, Grün

Sichern Sie den grünen Nachweis. Legen Sie auf demselben PR-Head die isolierte Datei `tests/test_ci_probe.py` an.

```python
def test_ci_gegenprobe():
    assert False, "Absichtliche RelNotes-CI-Gegenprobe"
```

1. Committen und pushen Sie die Probe selbst. Warten Sie auf den roten Check. Prüfen Sie den Testlog und die Merge-Anzeige, ohne einen Merge auszulösen. Ein roter Check belegt die Fehlererkennung. Eine Sperre ist erst anhand der Regeln und der Anzeige für die getestete Rolle belegt.
2. Geben Sie dem vorhandenen Cloud-Lauf höchstens einen Folgeauftrag, wenn im Kursbudget verfügbar. „Entferne ausschließlich die bekannte Datei tests/test_ci_probe.py von [PR/Head]. Keine Änderungen an Produktcode, Workflow oder echten Tests. Führe pytest aus und pushe auf den Head. Kein Merge.“ Alternativ entfernen und pushen Sie die Datei selbst.
3. Vergleichen Sie den Enddiff mit dem Stand vor der Probe. Prüfen Sie den neuen grünen Check und lassen Sie den aktuellen Stand erneut reviewen.

## 30–45 Min · Entscheidung und Release-Bezug

Halten Sie die drei Head-SHAs und Run-Links, Review-Status, offene Punkte und „freigeben“ oder „zurückstellen“ fest. Ein berechtigter Mensch kann den Sandbox-PR nach erfolgreicher Abnahme übernehmen. Release-Entscheidung separat festhalten. Besprechen Sie, welche integrierte SHA ein Tag zeigen müsste und warum der Tag-Workflow erneut testet. Tag und Veröffentlichung sind eine optionale Trainerdemo in einem separaten Wegwerf-Repo.

**Fallback.** Ab Lab-Minute 30 bei wartenden Checks lokal dieselbe Gegenprobe und Entfernung ausführen. Run-IDs als ausstehend markieren. Ohne GitHub lassen sich Trigger, Required Checks und Merge-Sperre nur besprechen.
